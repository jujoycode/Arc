# Arc 디자인 가이드

> 상태: 첫 릴리스 기준안 · 2026-10-04

## 1. 제품 경험

Arc는 작은 팀이 오늘 할 일과 일정·스프린트의 진행 상황을 빠르게 파악하는 작업 도구다. **KRDS(대한민국 정부 디자인 시스템)의 디자인 원칙, 접근성 기준, 토큰 구조와 공통 컴포넌트를 기반**으로 삼고, Arc의 복잡한 프로젝트 관리 화면에 필요한 패턴을 제품 디자인 시스템으로 확장한다. 프로젝트, 이슈, 일정이 먼저 보이고 장식은 작업을 방해하지 않는 수준으로 제한한다.

KRDS를 그대로 복제하지 않는다. KRDS의 기반 토큰과 컴포넌트 규칙을 검토한 뒤 Arc의 브랜드 색·상태 표시·간트 차트·보드처럼 필요한 제품 계층을 별도로 정의하고, 차이를 이 문서에 기록한다.

### 원칙

1. **한 이슈, 두 보기:** 칸반과 스크럼에서 동일한 이슈 이름, 상태, 담당자 표시를 사용한다.
2. **현재 위치가 명확해야 한다:** 워크스페이스, 프로젝트, 현재 보기, 선택한 스프린트를 항상 확인할 수 있다.
3. **자주 하는 작업은 가까이 둔다:** 이슈 생성, 담당자 지정, 상태 변경, 검색은 해당 화면에서 바로 실행한다.
4. **행동의 결과를 보여 준다:** 저장, 이동, 실패, 권한 부족을 즉시 알리고 실패한 입력은 보존한다.
5. **마우스 없이도 사용할 수 있다:** 드래그 기능에는 키보드로 조작할 수 있는 대체 메뉴를 제공한다.
6. **시간 정보는 정확하고 읽기 쉬워야 한다:** 간트 막대뿐 아니라 시작·종료일, 진행률, 지연·의존 관계를 텍스트와 도형으로도 확인할 수 있다.

## 2. 정보 구조

```text
워크스페이스
├─ 프로젝트 목록
│  └─ 프로젝트
│     ├─ 칸반 보드
│     ├─ 백로그
│     ├─ 진행 중 스프린트
│     ├─ 간트 차트
│     ├─ 이슈 목록
│     └─ 프로젝트 설정
└─ 팀 설정: 멤버·초대
```

- 데스크톱: 왼쪽 프로젝트 탐색(폭 240px), 상단 프로젝트 제목·보기 전환·주요 액션, 오른쪽 본문.
- 모바일: 탐색을 여닫는 메뉴로 옮기고, 보드는 가로 스크롤한다. 이슈 상세는 전체 화면으로 연다.
- 이슈 상세는 고유 URL을 가진다. 데스크톱에서 패널로 열더라도 새로고침과 링크 공유가 가능해야 한다.
- 목록·보드·백로그는 같은 검색어와 필터 규칙을 사용한다.

## 3. 시각 언어

### 토큰 계층

`KRDS 기준 → Arc 기본 토큰 → Arc 의미 토큰 → 컴포넌트 토큰 → 화면 패턴` 순서로 관리한다. 색·글자·간격·모서리·포커스 값을 화면에 직접 반복해 적지 않는다. 예를 들어 `--arc-color-action-primary`는 Arc 브랜드 색을 가리키고, 간트의 오늘 선은 `--arc-gantt-today-line`처럼 제품 토큰으로 참조한다. 기본 토큰을 바꾸면 보드·간트·폼에 같은 기준이 적용되어야 한다.

### 색상 토큰

| 용도 | 값 | 사용 |
| --- | --- | --- |
| 바탕 | `#F7F8FA` | 앱 배경 |
| 표면 | `#FFFFFF` | 카드·패널·대화상자 |
| 기본 글자 | `#17212F` | 제목·본문 |
| 보조 글자 | `#5F6B7A` | 메타 정보 |
| 경계 | `#D9E0E8` | 입력·구분선 |
| 주 행동 | `#315CF5` | Arc 브랜드 확장 토큰: 주요 버튼·활성 탐색 |
| 위험 | `#B42318` | 삭제·오류 |

상태는 글자와 아이콘/레이블을 함께 사용한다. 색만으로 의미를 전달하지 않는다.

| 상태 | 배경 | 글자 |
| --- | --- | --- |
| 할 일 | `#EEF1F4` | `#405164` |
| 진행 중 | `#EAF1FF` | `#1D4ED8` |
| 검토 | `#FFF3D6` | `#92400E` |
| 완료 | `#E7F5EB` | `#166534` |

### 글자·간격·형태

- 기본 글꼴: KRDS에서 사용하는 Pretendard GOV, 실패 시 시스템 고딕 글꼴. 글꼴을 불러오지 못해도 레이아웃이 유지되어야 한다.
- 본문 기본 17px, 최소 16px. 보조 정보도 읽기 어려운 크기로 낮추지 않는다. 페이지 제목은 24px 이상, 본문 행간은 최소 1.5.
- 글자 두께는 주로 400/700을 사용하고 필요한 경우 500을 보조적으로 쓴다.
- 간격은 4px 단위로 사용한다. 주로 8/12/16/24/32px를 쓴다.
- 카드·입력·버튼의 모서리 반경은 8px, 대화상자는 12px.
- 그림자는 패널의 높낮이를 구분할 때만 약하게 사용한다.

## 4. 주요 구성 요소

| 요소 | 기준 |
| --- | --- |
| 기본 버튼 | 행동을 동사로 명명한다. 화면마다 주 버튼은 한 개를 원칙으로 한다. |
| 입력 필드 | 항상 보이는 레이블, 필수 표시, 필드 가까이 오류 문구를 제공한다. |
| 이슈 카드 | 이슈 번호·제목·유형·우선순위·담당자를 표시한다. 긴 제목은 두 줄까지만 보이고 전체 내용은 상세에서 읽는다. |
| 상태 배지 | 모든 화면에서 같은 레이블과 색을 사용한다. |
| 필터 | 적용 상태를 눈에 띄게 보여 주고 한 번에 초기화할 수 있다. |
| 대화상자 | 삭제·스프린트 종료처럼 영향이 큰 작업에만 사용한다. |
| 알림 | 성공은 짧게, 실패는 원인과 재시도 방법을 보여 준다. |

### 보드

- 네 개의 기본 상태 열을 사용하며 열 너비는 데스크톱에서 약 300px로 잡는다.
- 열 머리글에 상태 이름과 현재 필터 기준 이슈 수를 표시한다.
- 드래그 중 대상 열을 강조한다. 이동이 실패하면 카드를 이전 위치로 돌리고 이유를 표시한다.
- 카드 메뉴 또는 상세 화면에서도 상태를 바꿀 수 있어야 한다.

### 백로그와 스프린트

- 백로그는 스프린트에 속하지 않은 이슈를 우선순위 순서대로 보여 준다.
- 계획 중/진행 중/완료된 스프린트를 서로 다른 표제로 구분한다.
- 스프린트 시작·종료 전에는 포함 이슈 수, 스토리 포인트, 미완료 이슈 처리 방식을 확인한다.

### 간트 차트: Arc 제품 패턴

- 왼쪽에는 프로젝트 → 버전/마일스톤 → Epic → Story·Task·Bug → 하위 작업의 계층과 이슈 번호를, 오른쪽에는 같은 행의 타임라인을 둔다. 행·스크롤 위치는 양쪽에서 일치해야 한다.
- 날짜 머리글은 확대 수준에 따라 월·주·일을 보여 준다. 시작 월, 표시 개월 수, 이전/다음 기간, 확대/축소를 제공한다.
- 이슈 기간 막대에 완료율을 함께 표현한다. 오늘 선, 휴무일 음영, 마일스톤 표식, 선행·차단 관계선을 구별해 표시한다.
- 막대 위에만 정보를 숨기지 않는다. 키보드로 행을 선택하면 시작·종료일, 완료율, 연결된 이슈를 텍스트로 읽고 이슈 상세로 이동할 수 있다.
- 관계선·진행률·지연 상태는 색과 함께 선 모양, 아이콘, 텍스트 레이블을 사용한다. 밀집 화면에서도 초점 표시와 선택 행 강조를 유지한다.
- 표와 차트가 좁아지면 타임라인을 가로 스크롤하고 계층 열은 읽을 수 있는 너비를 유지한다. 모바일에서는 행 상세 보기와 필터가 우선이다.
- 인쇄·PDF·PNG에서도 제목, 기간, 범례와 읽을 수 있는 해상도를 유지한다.

## 5. 반응형·접근성

- 기준 폭: 모바일 360px 이상, 태블릿 768px 이상, 데스크톱 1200px 이상.
- 키보드 포커스는 2px 이상 윤곽으로 분명히 표시한다. Tab 순서는 화면의 읽기 순서와 같아야 한다.
- 아이콘 단독 버튼에는 접근 가능한 이름을 제공한다. 대화상자는 포커스를 가두고 닫을 때 원래 위치로 돌린다.
- 본문·컨트롤 대비는 WCAG AA를 목표로 검증한다.
- KRDS의 선명한 화면 모드와 글자 확대 원칙을 고려한다. 200% 확대와 운영체제 고대비 설정에서 주요 행동과 일정 정보가 사라지지 않아야 한다.
- 움직임을 줄이도록 설정한 사용자는 드래그·전환 애니메이션 없이도 동일한 작업을 마칠 수 있어야 한다.
- 로딩 중에는 골격 화면이나 진행 상태를 보이고, 빈 상태에는 다음 행동을 안내한다.
- 오류와 성공 메시지는 보조 기술에도 전달한다.

## 6. 문구 원칙

- 화면 문구는 한국어를 기본으로 한다. `이슈 만들기`, `스프린트 시작`, `백로그로 이동`처럼 구체적인 동사를 사용한다.
- 삭제·종료 확인에서는 영향을 설명한다. 예: `미완료 이슈 3개가 백로그로 이동합니다.`
- 저장되지 않은 변경이 있을 때 이동하면 변경 내용을 잃을 수 있음을 알려 준다.

## 7. 후속 확장

다크 모드, 사용자별 밀도 설정, 맞춤형 상태 색은 첫 릴리스 이후에 검토한다. Arc 고유의 간트·보드 패턴은 구현하면서 토큰, 상태, 키보드 동작을 이 문서에 계속 추가한다.
