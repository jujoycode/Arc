## 1. 현재 화면 진단

| 발견 | 사용자 영향 | 설계 결정 |
| --- | --- | --- |
| 로그인해야만 제품 화면을 볼 수 있고 `index.html`을 파일로 열면 React 모듈이 실행되지 않는다 | 디자인 확인이 어렵다 | 백엔드 없이 여는 독립형 `frontend/public/design-preview.html`을 제공하고, 실제 앱은 Vite 주소로 안내한다 |
| 프로젝트 위치가 왼쪽 카드와 상단 이름으로 나뉜다 | 하위 프로젝트와 현재 맥락이 흐리다 | 상단에 워크스페이스 / 프로젝트 경로, 왼쪽에 프로젝트 전환과 주요 보기만 둔다 |
| 간트 기간 조작, 필터, 열 옵션, 보기 저장, 출력이 여러 줄에 흩어진다 | 자주 쓰는 기능을 찾기 어렵다 | 1행 기간·보기·출력, 2행 검색·필터, 세부 표시 옵션은 명시적 팝오버로 묶는다 |
| 보드 카드마다 큰 상태 선택 상자가 반복된다 | 제목보다 조작이 먼저 보이고 카드가 커진다 | 카드에는 제목·유형·우선순위·담당자·기한을 우선 표시하고 상태 이동은 메뉴 또는 드래그로 제공한다 |
| 11~13px 메타 글자가 넓게 쓰인다 | 밀집 화면에서 읽기 어렵다 | 메타 최소 13px, 카드 제목 15px, 본문 16px을 기준으로 다시 배치한다 |
| 공통 색과 간트 유형 색이 컴포넌트에 직접 입력되어 있다 | 일관성과 대비 관리가 어렵다 | KRDS → Arc 기본 → 의미 → 컴포넌트 → 간트/보드 패턴 토큰을 분리한다 |
| 모바일은 데스크톱 사이드바를 가로로 나열한다 | 현재 위치와 핵심 동작이 사라진다 | 상단 프로젝트 선택, 하단 주요 보기, 간트 표/시간축 분리 탐색을 설계한다 |

## 2. 제품 구조

```text
전역 상단: Arc / 워크스페이스 선택 / 프로젝트 경로 / 검색 / 내 계정
프로젝트 왼쪽: 개요 · 간트 · 보드 · 백로그 · 스프린트 · 이슈 · 설정
화면 상단: 위치 → 제목 → 현재 기간·결과 수 → 주요 작업
화면 본문: 필터 → 데이터 보기 → 선택 상세
```

- 프로젝트를 새로 열면 간트를 기본 보기로 제공하되, 이후 마지막으로 사용한 보기를 기억한다.
- 이슈의 제목과 상태를 여러 화면에서 같은 단어와 형태로 표시한다. 고유 이슈 키는 항상 상세 링크다.
- 검색·필터·선택 상태는 보기를 전환해도 가능한 범위에서 유지한다. 적용된 필터는 칩과 결과 수로 보인다.
- 화면 별 주 행동은 간트의 `이슈 만들기`, 보드의 `이슈 만들기`, 스프린트의 `스프린트 계획`처럼 한 개를 강조한다.

## 3. Arc 디자인 시스템 v2

### KRDS 계승과 Arc 확장

KRDS의 명확한 레이블, 상태 피드백, 키보드 탐색, 포커스 표시, 색 대비를 기본으로 삼는다. Arc가 추가하는 것은 밀집 데이터 표, 프로젝트 계층, 간트 타임라인, 칸반 카드, 스프린트 상태다. KRDS 컴포넌트와 다른 동작은 별도의 Arc 패턴으로 문서화한다.

| 토큰/규칙 | 제안 기준 | 적용 |
| --- | --- | --- |
| 본문 글자 | 16px / 행간 1.5 | 설명·폼·본문 |
| 메타 글자 | 최소 13px / 행간 1.4 | 이슈 키·날짜·담당자 |
| 화면 제목 | 30px / 700 | 현재 보기 |
| 카드 제목 | 15~16px / 650 | 보드와 백로그 |
| 표/간트 행 | 기본 48px, 편안한 밀도 56px | 사용자 밀도 설정의 기반 |
| 기본 간격 | 4px 계열, 주로 8/12/16/24/32px | 전체 |
| 기본 조작 높이 | 최소 40px, 주요 버튼 44px | 폼·툴바 |
| 포커스 | 외곽선 3px 및 2px 간격 | 키보드 접근 |
| 주 색 | 기존 Arc 파랑을 유지, 대비를 검증해 조정 | 행동·선택 |
| 유형/상태 색 | 의미 토큰으로 분리하고 텍스트·아이콘 병기 | 간트·보드 |

상태, 우선순위, 유형 배지는 `라벨 + 색`을 함께 사용한다. 간트 관계는 실선/점선과 텍스트 목록을 병행한다. 오류는 문제와 복구 행동을 함께 제공하고 입력 내용을 보존한다.

### 핵심 컴포넌트 계약

- **App shell:** 상단 64px, 왼쪽 232px, 본문 최대 너비 제한은 목록·설정에만 적용. 간트는 가용 폭을 모두 쓴다.
- **Page header:** 경로, 제목, 설명, 요약 수치, 주요 행동. 높이가 부족한 모바일에서는 설명을 접어도 경로·제목·행동은 보인다.
- **Filter bar:** 검색, 핵심 필터 2~3개, 추가 필터, 초기화, 적용 결과 수. 선택 조건은 다시 열어 확인할 수 있다.
- **Issue card:** 키·유형, 제목, 우선순위·담당자·기한, 상태 이동 메뉴. 카드 전체가 상세 링크로 동작하되 메뉴는 별도 초점 요소다.
- **Issue table:** 서버 페이지, 열 제목 정렬, 총 결과 수, 페이지 크기. 행의 키와 제목을 읽을 수 있다.
- **Gantt row:** 프로젝트·버전·Epic·작업 계층, 날짜/완료율, 선택/접기 키보드 조작. 선택 상세는 차트를 밀어내지 않는 측면 패널을 목표로 한다.
- **Dialog:** 제목·영향 설명·취소·확정. 파괴적 행동은 확인 내용을 구체적으로 쓴다.

## 4. 화면별 재설계

1. **로그인·첫 시작:** Arc 가치 한 문장, 이메일 입력, 오류/검증 메일 안내를 명확히 한다. 첫 워크스페이스 생성까지 한 흐름으로 연결한다.
2. **워크스페이스:** 프로젝트 목록을 계층으로 보여 주고, 최근 작업과 진행 중 스프린트를 요약한다. 빈 상태에는 프로젝트 만들기 행동을 둔다.
3. **간트:** 기간 조작과 필터를 분리한다. 좌측 계층 표의 이름·완료율을 읽을 수 있게 유지하고 시간축을 가로 스크롤한다. 프로젝트·버전·Epic 집계와 관계 설명을 선택 상세에서 확인한다.
4. **보드:** 열 머리글에 개수와 의미를 표기한다. 카드 높이를 줄이고 상태 변경 메뉴를 카드 우상단으로 옮긴다. 실패 시 이전 열로 돌아오고 오류 이유를 보여 준다.
5. **백로그·스프린트:** 미편성/계획/진행/종료를 화면에서 구별한다. 스프린트 종료 전 미완료 이슈 이동 위치와 수치를 표시한다.
6. **이슈 상세·설정:** 본문과 속성의 읽기 순서를 고정한다. 댓글 편집·관계 해제·권한별 행동이 발견 가능해야 한다. 위험한 설정은 별도 구획에 모은다.

## 5. 반응형·접근성 수용 기준

- 360px, 768px, 1280px에서 가로 문서 스크롤 없이 탐색·생성·상태 변경이 가능하다. 간트 시간축과 보드 열 자체의 가로 스크롤은 허용하고 명시한다.
- 200% 확대에서 헤더·주요 버튼·필터가 겹치지 않는다.
- 키보드로 프로젝트 선택 → 보기 전환 → 필터 → 이슈 선택 → 상세 열기 → 상태 변경을 마칠 수 있다.
- 주요 텍스트와 컨트롤은 WCAG AA 대비를 만족한다. 색만으로 상태·유형·관계를 전달하지 않는다.
- 로딩/빈 목록/권한 없음/저장 충돌/네트워크 실패를 각 화면의 실제 상태로 설계한다.
