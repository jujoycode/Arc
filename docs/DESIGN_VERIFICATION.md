# Arc 디자인 시스템 v2 검증

> 갱신일: 2026-10-08 · 기준: [디자인 가이드](DESIGN_GUIDE.md), [재기획](DESIGN_REPLAN.md)

## 적용 범위

- 기본 → 의미 → 컴포넌트 → 패턴 토큰을 정의하고 shadcn/ui·Tailwind v4에 연결했다.
- 앱 셸에 워크스페이스 위치, 실제 프로젝트 선택, 계정과 로그아웃을 적용했다. 모바일은 하단 보기 탐색을 사용한다.
- 간트 기간·출력, 필터, 표시 옵션, 개인 보기를 구분했다. 간트 좌측 계층·시간축은 48px 행을 공유하며, 완료·남은 구간과 관계선에 패턴 토큰을 적용했다.
- 칸반과 스프린트의 공통 이슈 카드에 상세 링크, 유형, 우선순위, 담당자, 포인트, 완료 예정일과 키보드 상태 선택을 제공한다.
- 백로그·목록의 글자·입력·정렬 조작을 통일하고 적용 필터를 개별 해제할 수 있게 했다.
- 설정과 생성 폼에 지속적으로 보이는 레이블을 적용하고 팀원 관리 버튼이 좁은 화면에서 줄바꿈되도록 했다.

## 재현 가능한 검사

`pnpm --dir frontend check:browser`는 자체 워크스페이스·프로젝트·이슈·멤버를 만든 뒤 아래를 검사하고 워크스페이스를 정리한다. API·MySQL·메일 수신함이 필요하며 실행 주소는 [개발·검증 안내](DEVELOPMENT.md)를 따른다.

| 검사 | 대상 |
| --- | --- |
| axe WCAG 2 A/AA, 2.1 A/AA, 2.2 AA 자동 규칙 | 이슈 생성 대화상자, 간트·WBS·타임라인·칸반·백로그·스프린트·이슈 목록·설정, 하위 티켓 생성 대화상자 |
| 문서 가로 넘침 | 각 화면 360·768·1280 CSS px |
| 확대 시 재배치 | 1440 물리 px에 해당하는 720 CSS px / DPR 2 환경 |
| 키보드 대체 동작 | 간트 항목 선택, 네이티브 카드 상태 변경, 표시 옵션 펼치기 |
| 운영체제 표시 설정 | forced colors + reduced motion에서 간트 옵션 조작 |
| 실패 상태 | 상태 이동 409 후 이전 상태 유지와 재시도, 편집 충돌 시 입력 보존 |
| 출력 | 선택 기간·열의 PNG 크기와 PDF 형식 |

접근성 결과 JSON은 `ARC_TEST_OUTPUT` 아래에 저장한다. CI에서는 `acceptance-artifacts`에 포함한다. 실패 시 스크린샷과 Playwright 추적을 함께 남긴다.

자동 검사에서 위반 0건을 확인했다. 이 결과는 수동 화면 읽기 도구 검증이나 전체 WCAG 인증을 의미하지 않는다. 확대 검사는 브라우저 네이티브 줌 조작 대신 같은 CSS 화면 폭과 DPR로 재배치를 검증한다. 실기기 화면 읽기 도구, 다크 모드, 사용자별 밀도, 마지막 보기 기억은 후속 검토 항목이다.

## 실제 제품 화면

2026-10-08 전체 구현 화면과 주요 기능 상태를 [제품 화면 안내](product/README.md)에 모았다. 실제 앱·API·MySQL과 같은 데모 팀을 사용한 사진 41장의 원본은 모두 1920×1080이다. 관리자·개발자 WBS, 타임라인·테이블·칸반·스프린트, 티켓 생성·실행·계획 편집·충돌, 인증·초대·설정·GitHub/GitLab 연동, 빈 프로젝트·보관 상태를 포함한다. [재촬영 도구](../scripts/product/README.md)는 폰트·조회·배치가 완료된 실제 브라우저 한 프레임을 저장하고 크기를 확인한다. UI 합성이나 이미지 확대는 하지 않았다. 연동은 로컬 제공자 모형으로 촬영했다. 이번 자료 갱신은 문서·사진 작업이며 기존 자동 접근성 검사 범위를 확장했다고 주장하지 않는다.

2026-10-06 연동 기능을 추가한 뒤 개발 활동·저장소 연결/전달 기록 화면의 axe 규칙과 360/768/1280px·200% 상당 재배치를 확인했다. 입력 레이블·토큰 입력 비움·검증키의 로컬 상태·실제 개발 링크 표시를 브라우저 수용 검사에 추가했다.

2026-10-07 간트 계층 검증에서는 Epic·Story·하위 작업의 들여쓰기, Enter·Space 접기, 모든 자손의 행·막대 숨김, 하위 부모의 접힘 상태 보존, 다른 가지의 독립성, 프로젝트·버전과 전체 접기·펼치기를 확인했다. 필터 변경·초기화 후에도 상태와 집계 값이 유지되며 숨겨진 끝점을 갖는 관계선은 제거된다. PNG 높이는 `72 + 보이는 행 수 × 48`과 일치했고 PDF 다운로드도 통과했다. 접힌 화면의 axe 결과는 위반 0건·통과 29개·수동 판단 필요 2개이며, 전체 기능 흐름과 360/768/1280px·확대 재배치 검사가 통과했다. 화면과 결과 JSON은 CI의 수용 검사 자료에 포함된다.

2026-10-07 WBS·타임라인·테이블 확장 검증이 통과했다. WBS의 계층 코드와 조상 맥락·중첩 접기·키보드·하위 생성, 말단 합계와 간트 집계 일치, 타임라인의 월/3개월·Epic/버전 그룹·경계 자르기·한쪽 날짜·미계획·기간 밖·상속 역전·상세 편집 반영, 표의 필수 열·선택 열·서버 정렬·보기 이동 중 유지·복원을 확인했다. 스타일 충돌을 해결한 뒤 전체 브라우저 수용 흐름을 다시 검증했다.

WBS·타임라인을 포함한 8개 주요 화면의 axe 위반 0건과 360/768/1280px·확대 재배치가 통과했다. 새 하위 티켓 대화상자도 위반 0건이다. CI 수용 자료에 `wbs-1920.png`와 `timeline-1920.png`를 1920×1080으로 보관한다. 새 뷰의 대량 데이터 성능·실기기 화면 읽기 도구는 이번 기능 수용 검사 범위 밖이다.

CI 반복 실행에서 발견한 WBS 활성화 중 버튼 대비 문제는 초기 조회 완료 전 명시적 로딩 표시와 투명도 전환 제거로 해결했다. 조회를 지연시켜 로딩 안내·조작 비노출·axe 위반 0건을 확인하고 전체 기능 검증을 다시 통과했다. 1920×1080 캡처는 폰트·뷰포트 재배치 완료와 맨 위 위치를 확인한 뒤 촬영한다.

WBS 역할 확장에서는 개발자의 전체 팀 조회·내 업무 전환·조상 맥락과 팀 합계 유지, 실행 전용 폼의 충돌 입력 보존, 추가 관리자 지정·해제·기본 관리자 유지와 프로젝트 격리, 미배정 업무·조회 실패 후 재시도를 확인했습니다. 관리자 생성·상세 계획 편집과 개발자 조회 화면을 같은 브라우저 흐름에서 검증했습니다. 총 18개의 axe 상태/화면에서 위반 0건이며 개발자 WBS의 360/768/1280px·확대 재배치도 통과했습니다. `wbs-developer-1920.png`를 1920×1080 수용 자료로 보관합니다.
