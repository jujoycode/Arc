# arcat 폼 디자인과 검증 규칙

> 갱신일: 2026-10-10 · 구현 기준
> 관련 문서: [디자인 가이드](DESIGN_GUIDE.md), [티켓 필드 설정](TICKET_FIELDS_PLAN.md)

관리자는 계획을 정확히 입력하고, 개발자는 담당 업무의 진행 상황을 빠르게 갱신한다. KRDS의 레이블·설명·오류 원칙을 Arc의 업무 흐름과 shadcn/ui 구성 요소에 적용한다.

## 화면과 입력 구조

| 항목 | 규칙 |
| --- | --- |
| 레이블 | 입력 위에 왼쪽 정렬, 14px. 모든 컨트롤에 연결된 레이블 제공 |
| 필수·선택 | 필수 입력을 글자로 표시하고 색상에만 의존하지 않는다 |
| 설명 | 레이블 아래 한 문장으로 입력 목적·조건·단위 안내 |
| 폭 | 계획 폼 최대 960px, 실행 폼 560px. 긴 본문은 전체 열 사용 |
| 배치 | 넓은 화면은 두 열, 좁은 화면은 한 열. 필드 간 16px, 그룹 간 24px 이상 |
| 그룹 | 기본 정보 / 계획·배정 / 일정·추정 / 진행 상황 / 추가 정보. fieldset·legend 사용 |
| 단위 | 완료율은 %, 추정치는 포인트. 빈 숫자와 0을 구분 |
| 동작 | 취소 다음 저장 순서. 저장 중 중복 제출 방지 |
| 대화상자 | 제목·동작을 확인할 수 있는 높이와 본문 스크롤. 오류는 해당 대화상자 안에 표시 |

생성과 계획 편집은 같은 입력 구성을 사용한다. 실행 폼은 상태와 완료율을 제공하며, 추가 필수 계획 필드 때문에 개발자의 진행 보고가 차단되지 않는다. 워크스페이스의 표준 필드 순서는 해당 그룹 안에 적용한다.

## 검증과 오류 안내

- 첫 제출에서 전체 입력을 검사한다. 오류가 발생한 필드는 수정 시 다시 검사한다.
- 오류 메시지는 해당 필드 바로 아래에 표시한다. `aria-invalid`와 `aria-describedby`로 입력·설명·오류를 연결한다.
- 제출 오류 요약에서 첫 잘못된 입력으로 이동한다. 입력값은 실패 후에도 유지한다.
- 날짜 형식뿐 아니라 실제 날짜와 시작일·마감일 순서를 검사한다. 숫자는 빈 값, 정수, 범위, 유한성을 명시적으로 검사한다.
- 후보 목록의 로딩·실패·빈 목록을 구분한다. 실패 시 다시 불러오기를 제공한다.
- 서버의 필드 오류를 같은 위치에 연결하고 권한·네트워크 오류는 폼 안에 안내한다.
- 티켓 버전 또는 필드 설정 충돌은 입력 오류와 구분한다. 사용자의 초안을 유지하고 다시 확인할 방법을 제공한다. 자동으로 최신 버전을 붙여 덮어쓰지 않는다.
- 비활성 필드·선택지는 기존 값을 보존한다. 설정 변경이나 단순 조회가 데이터 삭제를 일으키지 않는다.

## 타입과 API 경계

Valibot 스키마에서 입력 타입을 도출하고, 제출 전에 폼 값을 검사한다. 변경하는 API의 응답은 `unknown`에서 스키마로 검사한다. 서버는 Kotlin의 도메인·권한 검증을 최종 적용하며 클라이언트 검사에 의존하지 않는다.

기존 API 호출은 호환성을 유지한다. 오류 응답의 기존 `error` 문구에 코드와 필드별 오류를 추가하여 화면이 실패 원인을 구분하게 한다. 숫자 문자열을 무조건 `Number`로 바꾸어 빈 값이 0으로 저장되는 흐름을 제거한다.

## 수용 기준

- 관리자 계획 폼·담당자 실행 폼·워크스페이스 필드 설정에서 일관된 레이블·설명·오류·동작을 확인한다.
- 키보드만으로 입력과 오류 이동이 가능하고 작은 화면에서 가로 넘침이 없다.
- 잘못된 응답·날짜·숫자·필수값, 서버 오류와 충돌에서 초안이 유지된다.
- 프로젝트 관리자·담당자·일반 멤버·보관 프로젝트의 기존 권한을 유지한다.
- 실제 제품 화면 자료는 브라우저에서 1920×1080으로 촬영한다.
