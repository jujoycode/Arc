## 1. 목적과 범위

소규모 팀이 프로젝트의 이슈를 공동 관리한다. 같은 이슈를 간트 차트, 칸반 보드, 스크럼 백로그·스프린트 보드에서 다루며, 어느 화면에서 바꿔도 서버에 저장된 하나의 상태와 일정이 모든 화면에 반영된다. Redmine 수준의 간트 차트를 초기 구현 우선순위로 둔다.

첫 릴리스는 이메일 로그인, 팀 초대, 프로젝트, Epic·Story·Task·Bug·하위 작업, 댓글, 검색·필터, 간트, 칸반, 백로그, 스프린트 계획·실행·종료까지 포함한다. 파일 첨부, 알림, 맞춤형 워크플로, 자동화, 리포트, 외부 연동의 실제 연결은 포함하지 않는다. GitHub·GitLab 연동을 추가할 수 있도록 식별자와 이벤트 경계를 설계한다.

기존 항목의 ‘버전/마일스톤’은 현행 버전 기반 날짜 표현을 가리킨다. 독립 마일스톤은 2026-10-07의 추가 기획이며 아래 8절과 MIL 요구사항으로 구분한다. 현재 구현 여부는 [STATUS](STATUS.md)를 따른다.

## 2. 역할과 권한

| 작업 | 소유자 | 워크스페이스 관리자 | 멤버 |
| --- | :---: | :---: | :---: |
| 워크스페이스·프로젝트 조회 | ✓ | ✓ | ✓ |
| 팀원 초대·역할 변경 | ✓ | ✓ | — |
| 소유자 변경·워크스페이스 삭제 | ✓ | — | — |
| 프로젝트 생성·설정·보관 | ✓ | ✓ | — |
| 프로젝트 관리자 지정·해제 | ✓ | ✓ | — |
| 티켓 생성·계획 편집 | ✓ | ✓ | 해당 프로젝트 관리자 지정 시 |
| 상태·완료율 변경 | ✓ | ✓ | 담당 티켓 또는 프로젝트 관리자 |
| 티켓 조회·댓글 | ✓ | ✓ | ✓ |
| 이슈 삭제 | ✓ | ✓ | 프로젝트 관리자 |
| 스프린트 생성·시작·종료 | ✓ | ✓ | 프로젝트 관리자 |
| 백로그 이슈 정렬·스프린트 편성 | ✓ | ✓ | 프로젝트 관리자 |
| 간트 조회·개인 필터 저장 | ✓ | ✓ | ✓ |
| 이슈 선행·차단 관계 설정 | ✓ | ✓ | 프로젝트 관리자 |

- 사용자는 여러 워크스페이스에 속할 수 있다. 권한은 각 워크스페이스에서 따로 정한다.
- 프로젝트 관리자는 기본 OWNER·ADMIN과 프로젝트별로 지정한 팀원을 포함한다. 추가 지정은 워크스페이스 역할이나 다른 프로젝트 권한을 바꾸지 않는다. 티켓 계획·실행·댓글 관리·스프린트·버전 관리에 적용한다.
- 첫 릴리스에서 워크스페이스 멤버는 그 안의 모든 프로젝트를 볼 수 있다.
- 화면에서 숨기는 것만으로 권한을 처리하지 않는다. 모든 API는 로그인과 소속·역할을 다시 검사한다.

## 3. 화면과 경로

| 화면 | 주요 내용 |
| --- | --- |
| 로그인·초대 수락 | 이메일 로그인, 초대 대상 이메일 확인, 오류·만료 처리 |
| 워크스페이스/프로젝트 선택 | 참여한 워크스페이스와 프로젝트 목록, 새 프로젝트 만들기 |
| 칸반 보드 | 상태별 열, 이슈 카드, 검색·필터, 새 이슈 만들기 |
| 백로그 | 편성되지 않은 이슈 정렬, 계획 중 스프린트, 이슈 편성 |
| 스프린트 보드 | 진행 중 스프린트의 이슈를 상태별로 표시, 목표·기간·진척 |
| 간트 차트 | 계층형 이슈·버전, 기간·완료율, 관계선, 필터·확대·내보내기 |
| 이슈 목록 | 검색·필터·정렬과 이슈 상세 진입 |
| 이슈 상세 | 설명, 속성, 댓글, 변경 활동 |
| 팀·프로젝트 설정 | 멤버, 초대, 프로젝트 이름·키·설명 |

이슈 상세는 고유 주소를 가진다. 프로젝트 안에서 보기 전환을 해도 현재 검색·필터 조건을 가능한 범위에서 유지한다.

## 4. 기능 요구사항

### AUTH — 로그인과 초대

- **AUTH-01** 첫 구현의 기본안은 이메일·비밀번호 로그인이다. 가입 시 이메일을 검증하고, 비밀번호는 서버에서 안전한 해시로만 보관한다. 이메일 주소를 검증한 사용자만 로그인할 수 있다.
- **AUTH-02** 소유자·관리자는 이메일 주소와 역할을 지정해 팀원을 초대할 수 있다. 초대는 7일 뒤 만료되며 취소할 수 있다.
- **AUTH-03** 초대 수락 시 로그인된 사용자의 검증된 이메일이 초대 주소와 일치해야 한다. 일치하지 않으면 멤버십을 만들지 않는다.
- **AUTH-04** 이미 멤버인 주소를 중복 초대할 수 없다. 사용자는 로그아웃할 수 있다.
- **AUTH-05** 첫 가입자는 새 워크스페이스를 만들 수 있고 그 워크스페이스의 소유자가 된다.

### PROJ — 워크스페이스와 프로젝트

- **PROJ-01** 프로젝트는 이름, 설명, 고유 키를 가진다. 키는 영문 대문자로 시작하는 2~10자의 영문 대문자·숫자이며 워크스페이스 안에서 유일하다.
- **PROJ-02** 프로젝트 키는 첫 이슈가 생성된 뒤 변경할 수 없다. 이슈 번호의 안정성을 위한 규칙이다.
- **PROJ-03** 소유자·관리자는 프로젝트를 만들고 이름·설명을 수정할 수 있다. 보관된 프로젝트는 읽기 전용으로 남긴다.
- **PROJ-04** 프로젝트별 이슈 번호는 1부터 증가하며 동시에 생성해도 중복되지 않는다.
- **PROJ-05** 프로젝트는 같은 워크스페이스의 다른 프로젝트를 부모로 가질 수 있다. 간트에서 하위 프로젝트를 접고 펼칠 수 있으며 순환 계층은 허용하지 않는다.

### ISSUE — 이슈

- **ISSUE-01** 이슈 필수값은 제목(1~200자), 유형(Epic/Story/Task/Bug/하위 작업), 상태다. 상태 기본값은 `할 일`이다.
- **ISSUE-02** 선택값은 설명, 우선순위(낮음/보통/높음/긴급), 담당자, 시작일, 종료일, 완료율(0~100), 버전/마일스톤, 스토리 포인트(0 이상의 정수)다. 우선순위 기본값은 `보통`이다. 시작일은 종료일보다 늦을 수 없다.
- **ISSUE-03** 담당자는 같은 워크스페이스의 멤버만 지정할 수 있다. 작성자는 서버가 로그인 사용자로 기록한다.
- **ISSUE-04** 기본 상태는 `할 일`, `진행 중`, `검토`, `완료`다. 첫 릴리스에서는 상태 간 이동에 별도 승인 규칙이 없다.
- **ISSUE-05** 이슈의 주요 속성 변경, 상태 이동, 담당자 변경, 스프린트 편성을 활동 기록에 남긴다.
- **ISSUE-06** 모든 멤버는 댓글을 작성할 수 있다. 본인은 자기 댓글을 수정·삭제할 수 있고 관리자 이상은 문제 댓글을 삭제할 수 있다.
- **ISSUE-07** 이슈 삭제는 관리자 이상만 가능하다. 삭제한 이슈 번호는 재사용하지 않으며 일반 목록에서 보이지 않는다.
- **ISSUE-08** 관리자는 상세에서 계획 속성과 실행 정보를 수정하고 멤버는 담당 티켓의 상태·완료율만 수정할 수 있다. 저장 실패 시 입력 내용을 보존한다.
- **ISSUE-09** Epic은 최상위 항목이다. Story·Task·Bug는 Epic에 속하거나 독립적으로 존재할 수 있다. 하위 작업은 Story·Task·Bug 중 하나에 속해야 하며, 부모와 같은 프로젝트에 속한다. 순환 계층은 허용하지 않는다.
- **ISSUE-10** Epic과 부모 이슈의 일정·진행률은 하위 항목을 바탕으로 집계해 표시한다. 이슈 간 선행·차단 관계를 등록·삭제할 수 있다.

### FIND — 검색과 필터

- **FIND-01** 프로젝트 안에서 이슈 번호 또는 제목으로 검색한다. 대소문자 구분 없이 검색한다.
- **FIND-02** 상태, 유형, 담당자, 우선순위, 버전, 스프린트 포함 여부로 필터링한다. 여러 종류의 필터를 함께 사용할 수 있다.
- **FIND-03** 필터 적용 상태와 결과 수를 표시하고 전체 필터를 초기화할 수 있다.
- **FIND-04** 긴 결과는 페이지 단위로 조회한다. 이슈 목록은 최신 변경 순서를 기본 정렬로 사용한다.

### KAN — 칸반

- **KAN-01** 프로젝트의 보관되지 않은 이슈를 기본 상태별 열에 표시한다. 스프린트 미편성 이슈도 표시한다.
- **KAN-02** 드래그 또는 상태 변경 메뉴로 다른 열에 옮기면 서버의 이슈 상태를 갱신한다.
- **KAN-03** 이동 요청이 실패하면 이전 상태로 복원하고 오류를 알린다.
- **KAN-04** 카드에는 이슈 번호·제목·유형·우선순위·담당자를 표시하고 상세로 이동할 수 있다.

### GANTT — 일정·진행률 시각화

- **GANTT-01** Redmine의 간트와 같은 수준으로 일정이 있는 이슈·버전, 프로젝트와 부모/자식 계층, 기간 막대와 완료율을 표시한다. 세부 기준은 [Redmine 간트 기능 검토](GANTT_REFERENCE.md)를 따른다.
- **GANTT-02** 시작 월과 표시 개월 수를 선택하고 이전/다음 기간으로 이동한다. 월·주·일을 읽을 수 있도록 4단계 확대·축소를 제공한다.
- **GANTT-03** 오늘 선과 주말 음영, 버전/마일스톤 표식, 선행·차단 관계선을 표시한다. 관계선과 진행선은 별도 옵션으로 켜고 끌 수 있다.
- **GANTT-04** 이슈의 상태·담당자·유형·우선순위·버전 등으로 필터링하고 개인별 필터 보기를 저장할 수 있다. 표시할 정보 열도 선택할 수 있다.
- **GANTT-05** 이슈·버전 행에서 상세로 이동한다. 현재 권한·필터·기간을 적용한 PDF와 PNG를 내보낼 수 있다.
- **GANTT-06** 일정 변경은 이슈 상세에서 수행한다. 차트의 막대 드래그 편집은 첫 릴리스 범위가 아니다. 키보드만으로도 행·날짜·완료율·관계를 읽을 수 있어야 한다.
- **GANTT-07** 프로젝트·버전·Epic·Story/Task·하위 작업을 부모 기준의 중첩 계층으로 접고 펼친다. 각 부모를 접으면 자신은 남고 모든 자손의 행·막대와 숨겨진 항목의 관계선이 사라진다. 다시 펼칠 때 하위 부모의 개별 접힘 상태를 유지하며 다른 가지에 영향을 주지 않는다. 필터를 바꾸거나 초기화해도 접힘 상태를 유지하고 일치하는 항목의 조상을 표시한다. 전체 접기·펼치기를 제공하고, 부모 일정·완료율 집계는 접힘과 무관하게 전체 하위 이슈를 기준으로 계산한다. 키보드로 조작하고 펼침 상태를 읽을 수 있어야 하며 PNG/PDF는 현재 보이는 계층만 내보낸다. 접힘 상태는 현재 간트 화면에 머무는 동안 유지한다.

### SCR — 백로그와 스프린트

- **SCR-01** 백로그에는 현재 스프린트에 편성되지 않은 이슈를 표시한다. 관리자 이상이 순서를 바꿀 수 있다.
- **SCR-02** 관리자 이상은 이름·목표·시작일·종료일이 있는 스프린트를 계획 상태로 만든다. 종료일은 시작일보다 빠를 수 없다.
- **SCR-03** 관리자 이상은 이슈를 계획 중 스프린트에 편성하거나 백로그로 이동할 수 있다. 한 이슈는 동시에 한 스프린트에만 편성된다.
- **SCR-04** 프로젝트에 진행 중 스프린트가 없을 때만 스프린트를 시작할 수 있다. 시작 시 이슈 수와 스토리 포인트 합계를 보여 준다.
- **SCR-05** 진행 중 스프린트 보드는 해당 스프린트의 이슈만 상태별로 보여 준다. 상태 변경은 칸반 및 상세에도 반영된다.
- **SCR-06** 종료 시 완료/미완료 이슈 수와 스토리 포인트를 요약한다. 미완료 이슈를 백로그 또는 계획 중인 다음 스프린트로 이동하도록 선택한다.
- **SCR-07** 종료된 스프린트의 결과와 당시 포함된 이슈 기록은 이후 이슈를 옮겨도 유지한다.
- **SCR-08** 종료된 스프린트는 다시 시작할 수 없다. 프로젝트당 진행 중 스프린트는 최대 한 개다.

## 5. 데이터와 일관성 규칙

핵심 데이터는 `users`, `workspaces`, `workspace_members`, `invitations`, `projects`, `issues`, `issue_relations`, `versions`, `comments`, `issue_activities`, `sprints`, `sprint_issue_history`, `saved_views`로 구성한다.

- 모든 프로젝트·이슈·스프린트 조회는 워크스페이스 소속 확인 후 수행한다. 클라이언트가 보낸 워크스페이스 ID만 신뢰하지 않는다.
- 이슈 번호 발급, 스프린트 시작·종료, 미완료 이슈 이월은 트랜잭션으로 처리한다.
- 날짜·시간은 서버에서 UTC로 저장한다. 화면은 사용자 지역 시간으로 표시하며 기한은 날짜만 표시한다.
- 동시에 편집한 경우 오래된 화면이 새 값을 조용히 덮어쓰지 않도록 충돌을 알린다.
- 데이터베이스 변경은 마이그레이션 파일로 관리한다. 실제 비밀번호·메일 발송 설정은 저장소에 커밋하지 않는다.
- GitHub·GitLab 연동을 대비해 프로젝트 키와 이슈 번호는 안정적으로 유지한다. 외부 저장소 연결과 웹훅 처리는 별도 모듈 경계로 분리하고, 이슈 변경을 내부 이벤트로 발행할 수 있게 설계한다. 연동 비밀값은 서버에만 보관하고 중복 웹훅 처리는 멱등하게 처리한다.

## 6. 필수 수용 시나리오

1. 관리자가 팀원을 초대하고, 해당 이메일로 로그인한 사용자가 초대를 수락해 프로젝트를 본다.
2. 관리자가 티켓을 만들고 담당자를 지정한 뒤 담당 개발자가 칸반에서 `진행 중`으로 옮긴다. 이슈 상세와 스프린트 보드도 같은 상태를 보여 준다.
3. 백로그의 이슈를 계획 중 스프린트에 넣고 시작한다. 같은 프로젝트에서 두 번째 스프린트를 시작하려 하면 거부된다.
4. 스프린트를 종료하고 미완료 이슈를 백로그로 돌린다. 종료된 스프린트 결과에는 해당 이슈의 과거 참여 기록이 남는다.
5. 다른 워크스페이스의 사용자가 URL이나 API를 직접 호출해도 이슈를 읽거나 수정할 수 없다.
6. 동일 프로젝트에서 이슈를 동시에 생성해도 고유 번호가 중복되지 않는다.
7. 작은 화면과 키보드 조작만으로도 이슈 상태를 변경할 수 있다.
8. Epic과 Story·Task·하위 작업, 버전, 선행·차단 관계가 간트에 올바른 계층과 날짜로 나타난다.
9. 간트의 확대·필터·저장된 보기·PDF/PNG 출력이 권한과 현재 기간을 따른다.
10. Story를 접은 뒤 Epic을 접고 다시 펼쳐도 Story는 접힌 상태로 남는다. 해당 가지 밖의 이슈와 부모의 집계 일정·완료율은 그대로 유지된다. 프로젝트·버전 계층 및 전체 접기·펼치기에서도 같은 규칙을 따른다.

## 7. 기술 기준과 미결정 사항

- 프런트엔드: React 19 + TypeScript. 백엔드: Kotlin + Spring Boot. 데이터베이스: MySQL 8.
- 배포 환경과 메일 발송 서비스는 아직 선택하지 않았다. 개발 단계에서는 재현 가능한 로컬 실행 방법을 제공한다.
- 이메일·비밀번호 방식을 기본안으로 진행한다. 첫 관리자 초기화 방식과 팀 초대 메일 운영 방식은 인증 기능 구현 전에 확정한다.
- GitHub·GitLab 연동은 확장 가능한 구조를 먼저 만들고, 실제 연결 인증·웹훅·커밋 및 병합 요청 연결은 별도 릴리스에서 구현한다.

## 8. 추가 기획 — 명시적 마일스톤 (설계 완료·구현 대기)

세부 흐름·데이터·단계·수용 시나리오는 [마일스톤 기획](MILESTONE_PLAN.md)을 따른다. 아래 항목은 현행 ◆ 표현의 구현 완료를 의미하지 않는다.

- **MIL-01** 마일스톤은 프로젝트의 독립 목표이며 이름·목표일·달성 기준을 필수로, 설명·담당자·같은 프로젝트 버전 연결을 선택적으로 가진다. 한 버전에 여러 목표를 둘 수 있다.
- **MIL-02** 관리자·소유자는 생성·편집·선행 조건 변경·달성·취소·재개를 수행하고 멤버는 조회한다. 서버가 팀 소속·같은 프로젝트의 연결·담당자 소속·보관 상태를 검사한다.
- **MIL-03** 같은 프로젝트의 선행 이슈를 연결한다. 부모를 선택하면 말단 작업을 펼치고 중복 제거한 실제 DONE 수를 보여 준다. 0개는 수동 검증이며 삭제된 참조를 조용히 제거하지 않는다.
- **MIL-04** 계획·달성·취소 상태를 구분한다. 기한 초과는 계획 상태의 계산된 경고이며 날짜 경과나 작업 완료만으로 자동 달성하지 않는다.
- **MIL-05** 관리자가 실제 달성일과 검증 메모를 기록한다. 미완료·무효 참조의 예외 달성은 사유를 요구한다. 달성은 이슈·스프린트·버전 상태를 바꾸지 않는다.
- **MIL-06** 날짜 변경·취소·재개 사유와 전후 값, 달성 시 연결 범위·작업 상태·판단의 스냅샷을 보존한다. 이후 이슈 변경은 과거 달성을 소급 변경하지 않는다.
- **MIL-07** 간트에서 마일스톤은 프로젝트 또는 연결 버전의 말단 행이다. 계획일과 실제 달성일의 ◆를 명시적으로 표시하고 일반 이슈 기한·버전 목표와 구분한다. 이슈 계층·배정·일정을 바꾸거나 같은 이슈를 복제하지 않는다.
- **MIL-08** 조상 접기, 종류·이름 조회, 표시 옵션·저장 보기·상세 탐색·PNG/PDF가 새 행과 상태를 함께 처리한다. 이슈 관계선·완료율·진행선 집계에는 마일스톤을 넣지 않는다.
- **MIL-09** 날짜는 달력 날짜로 유지하고 기록 시각은 UTC로 저장한다. 기한 초과는 서버의 업무 시간대 기준으로 판단하며 기본 Asia/Seoul을 제안한다.
- **MIL-10** revision 충돌 시 입력을 보존한다. 달성 판단·상태 변경·이력은 프로젝트 잠금과 같은 트랜잭션에서 수행하고 부분 실패를 롤백한다.
- **MIL-11** 기존 버전과 시작일 없는 이슈를 자동 변환하지 않는다. 명시적 새 개체를 추가하고 기존 API·날짜 상속·저장 보기·계층 접기를 회귀 검증한다.

공통 마일스톤 필터·상단 요약·버전 배포 수명주기·SCM 증빙은 2차, 여러 프로젝트 공유·외부 마일스톤 동기화는 별도 후속 범위다.
