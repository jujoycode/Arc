# GitHub·GitLab 연동 설계 기준

> 상태: 후속 구현을 위한 구조 결정 · 실제 연결 기능은 첫 릴리스 범위 밖

## 사용자 목표

프로젝트에 코드 저장소를 연결하고 커밋, Pull Request 또는 Merge Request의 제목·본문에서 `ARC-123` 같은 이슈 키를 인식해 해당 이슈의 개발 활동으로 보여 준다. 연동이 없어도 Arc의 이슈·간트·보드는 독립적으로 작동한다.

## 경계

- `RepositoryProvider` 경계를 두고 GitHub·GitLab 인증, 저장소 조회, 웹훅 서명 검증, 이벤트 변환을 각각 구현한다.
- 두 제공자의 이벤트를 `CommitLinked`, `ChangeRequestOpened`, `ChangeRequestMerged` 같은 Arc 내부 이벤트로 정규화한다.
- Arc 프로젝트 키와 이슈 번호는 변경되지 않는 외부 참조로 사용한다. 키 일치만으로 이슈 상태를 자동 변경하지 않는다.
- 연결 단위는 Arc 프로젝트와 외부 저장소의 조합이다. 연결 생성·해제는 프로젝트 관리자 이상만 할 수 있다.
- 연결 비밀값은 서버에서 암호화해 보관하고 브라우저 응답·로그·Git 저장소에 넣지 않는다. 제공자별 최소 권한을 요청한다.
- 웹훅은 서명 검증, 전달 ID 기반 중복 제거, 재시도와 실패 기록을 갖춘다. 외부 API 장애가 Arc 이슈 저장을 막지 않도록 비동기로 처리한다.

## 이후 추가할 데이터

`repository_connections`(프로젝트·제공자·저장소 식별자·상태), `development_links`(이슈·외부 URL·종류·상태), `webhook_deliveries`(제공자 전달 ID·처리 결과)를 별도 마이그레이션으로 추가한다. 접근 권한을 잃은 연결은 비활성화하되 기존 이슈 데이터는 보존한다.

## 첫 연동 단계의 수용 기준

1. 관리자만 저장소를 연결·해제한다.
2. `ARC-123`이 포함된 커밋과 Pull/Merge Request가 해당 이슈에 한 번만 연결된다.
3. 존재하지 않거나 다른 워크스페이스의 이슈 키는 연결되지 않는다.
4. 웹훅 재전송, 순서 변경, 제공자 일시 장애에도 중복 또는 이슈 상태 오염이 없다.
