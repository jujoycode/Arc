# 구현 현황

> 갱신일: 2026-10-04 · 기준: [기능 명세](FUNCTIONAL_SPEC.md)

Arc의 목표는 팀이 하나의 이슈 데이터를 간트, 칸반, 스크럼에서 함께 관리하는 제품이다. 아래의 **화면 미리보기**는 샘플 데이터를 사용하며 실제 저장 기능의 완료를 뜻하지 않는다.

| 영역 | 현재 상태 | 남은 핵심 작업 |
| --- | --- | --- |
| 디자인 시스템 | KRDS 기반 가이드와 Arc 토큰 초안 작성, 간트 화면에 적용 | 공통 컴포넌트 규격·상태별 예시·접근성 검증 확대 |
| 기술 기반 | React 19, Kotlin/Spring Boot, MySQL 8, Flyway 초기 스키마와 보안 기본 차단 구성 | 실행 환경별 설정, API 계약, 배포 파이프라인 |
| 인증·팀 (`AUTH`) | 사용자·워크스페이스·멤버십·초대 테이블 준비 | 이메일 검증·로그인·초대·권한 검사 전체 |
| 프로젝트·이슈 (`PROJ`, `ISSUE`) | 프로젝트 계층·이슈 유형·부모·일정·관계·버전 스키마 준비 | 생성·수정·조회 API, 유효성 검사, 댓글·활동 기록, 이슈 상세 화면 |
| 검색 (`FIND`) | 간트 샘플 화면의 키·제목·담당자 검색, 유형·상태 필터 | 서버 검색·필터·페이지 처리, 전체 조건과 초기화 |
| 간트 (`GANTT`) | 샘플 화면에서 계층 접기/펼치기, 기간 막대·완료율, 월 이동·시작 월·표시 개월 수·4단계 확대, 오늘 선·주말·마일스톤·관계선, 유형·상태 검색/필터, 관계·완료율 표시 옵션, 키보드 선택·상세 요약 | 실제 API 데이터와 권한, 상위 일정/진척 집계, 담당자·우선순위·버전 필터, 개인 보기 저장·열 선택, 상세 이동, PDF/PNG 출력, 접근성 검증 |
| 칸반 (`KAN`) | 스키마 및 명세만 준비 | 상태별 보드, 서버 상태 변경, 실패 복원 |
| 스크럼 (`SCR`) | 스프린트 스키마 및 명세만 준비 | 백로그, 스프린트 계획·실행·종료와 이력 |
| GitHub·GitLab 연동 | 확장을 위한 식별자·이벤트 경계 문서 작성 | 실제 계정 연결·웹훅·이슈 연계는 첫 릴리스 이후 |

## 다음 구현 순서

1. 인증과 워크스페이스 권한을 구현한다.
2. 프로젝트·이슈 API와 일정·관계·버전 저장을 구현한다.
3. 간트를 실제 API에 연결하고 Redmine 기준의 필터 저장·출력을 완성한다.
4. 같은 이슈 API를 사용하는 칸반과 스크럼을 구현한다.

기능 명세의 완료 기준은 실제 로그인 사용자가 데이터를 저장하고 다른 기기에서 다시 조회할 수 있으며, 세 화면에서 상태가 일치하는 것이다. 현재 화면 미리보기는 이 기준을 충족하지 않는다.
