## 마일스톤 기획과 후속 구현

- [x] Redmine·Jira Cloud·GitLab·GitHub의 공식 문서를 비교하고 [현행 Arc와의 차이](MILESTONE_RESEARCH.md)를 기록했다.
- [x] 버전과 독립 마일스톤의 역할·달성 규칙·간트·데이터·권한·호환 전환을 [기획](MILESTONE_PLAN.md)하고 명세 MIL-01~11과 수용 시나리오를 정의했다.
- [ ] 1단계: 마일스톤 Flyway·Exposed·공개 계약·CRUD·권한·revision·이력 구현.
- [ ] 2단계: 선행 조건·말단 중복 제거·무효 참조·수동/예외 달성·증빙 스냅샷과 동시 변경 검증.
- [ ] 3단계: 목록·생성·상세·선행 조건·달성·취소·재개 UI와 실패 복원 구현.
- [ ] 4단계: 명시적 마일스톤·버전 목표·일반 기한 구분, 간트 접기·필터·저장 보기·PNG/PDF 통합.
- [ ] 5단계: 전체 수용·접근성·반응형·대량 데이터·CI 검증 후 실제 1920×1080 제품 화면과 문서 갱신.

위 구현 항목은 이번 조사·기획의 후속 작업이며 아직 구현하지 않았다. 추가 확장의 범위와 순서는 기획 문서의 9절을 따른다.

## 기존 요청의 후속 작업

- [x] 모든 JDBC 저장소를 Exposed DSL로 전환했다. 유스케이스의 트랜잭션·행 잠금·낙관적 잠금을 보존하고 MySQL의 동시 번호 발급·부분 변경 롤백·스프린트 결과 및 브라우저 수용 흐름을 검증했다.
- [x] 서버 필터와 보기 간 필터 상태 공유를 정리했다. 목록·보드·간트·백로그·스프린트에서 공통 조건을 유지한다.
- [x] 5,000개 이슈의 실제 API·간트·보드·백로그, 20,000개 간트 모델을 점검했다. 그룹 복사 제거·페이지 병렬 취합·백로그 100개 페이지·실패 복원과 재시도를 적용했다. [측정 범위와 제한](PERFORMANCE.md)
- [x] Docker Compose 앱·DB·메일 설치, 비관리자 웹·API 이미지, 상태 검사, SMTP 변수, 백업·복원과 Get Started를 준비했다. 새 설치의 전체 API·브라우저 및 별도 DB 복원을 검증했다. [배포 문서](DEPLOYMENT.md) · 운영 도메인·SMTP는 실제 서버에서 설정한다.
- [x] GitHub·GitLab 연결·암호화·서명·DB 큐·커밋/PR/MR 이슈 연결, 중복·순서·실패 재시도·권한 상실 및 설정·개발 활동 UI를 구현했다. 제공자 모형과 MySQL·브라우저·접근성·반응형 수용 검사가 통과했다. [연동 범위와 실계정 설정](INTEGRATIONS.md)
